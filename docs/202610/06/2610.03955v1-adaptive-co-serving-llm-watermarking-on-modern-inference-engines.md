## 摘要
大语言模型（LLM）水印对于所有权验证和知识产权保护具有重要意义。然而，现有方法主要关注算法设计，而将LLM推理引擎视为独立组件。这种分离常常引入辅助模型或外部工具，增加延迟和内存开销，同时限制了对现代推理优化的利用。因此，仍存在部署鸿沟：实用的水印必须在最小化服务开销的同时，保持效用、可检测性和鲁棒性。为弥合这一鸿沟，我们提出SWIFT，一个将LLM水印与现代推理基础设施协同设计的框架。SWIFT（i）在共享的LLM后端中集成文本生成和水印构建，以减少重复计算、提高缓存复用并简化系统复杂度；（ii）使用指令引导的候选生成与语义保护，以保持事实一致性和语义；（iii）通过异步协同服务和自适应调度，使水印与生成并发执行，以降低延迟并提高资源利用率；（iv）利用vLLM优化来提升服务效率。跨领域和任务的广泛实验表明，SWIFT在显著提升服务效率的同时，实现了强大的效用、可检测性、鲁棒性和下游性能。具体而言，它取得了最高效用分数（4.87）、99.65%的检测准确率（低延迟基线SynthID为76.65%），并在水印移除攻击下达到最高97.7%的检测率，且延迟比最高效用基线SafeSeal低5.9倍。这些结果证明了将水印与推理基础设施协同设计对实际LLM服务的益处。代码和工件可在以下网址获取：https://anonymous.4open.science/r/SWIFT-0597。

## Abstract
Large language model (LLM) watermarking is important for ownership verification and intellectual property protection. However, existing approaches focus on algorithmic design while treating LLM inference engines as separate components. This separation often introduces auxiliary models or external tools, increasing latency and memory overhead while limiting the use of modern inference optimizations. As a result, a deployment gap remains: practical watermarking must preserve utility, detectability, and robustness while minimizing serving overhead. To bridge this gap, we propose SWIFT, a framework that co-designs LLM watermarking with modern inference infrastructure. SWIFT (i) integrates text generation and watermark construction within a shared LLM backend to reduce re-computation, improve cache reuse, and simplify system complexity; (ii) uses instruction-guided candidate generation with semantic protection to preserve factual consistency and meaning; (iii) executes watermarking concurrently with generation through asynchronous co-serving and adaptive scheduling to reduce latency and improve resource utilization; and (iv) leverages vLLM optimizations to enhance serving efficiency. Extensive experiments across domains and tasks show that SWIFT achieves strong utility, detectability, robustness, and downstream performance while substantially improving serving efficiency. Specifically, it achieves the highest utility score (4.87), 99.65% detection accuracy compared with 76.65% for the low-latency baseline SynthID, and up to 97.7% detection under watermark removal attacks, with 5.9x lower latency than the highest-utility baseline, SafeSeal. These results demonstrate the benefits of co-designing watermarking with inference infrastructure for practical LLM serving. Code and artifacts are available at: https://anonymous.4open.science/r/SWIFT-0597.

## 2. 方法论

- **核心思想**：在共享的单一 LLM 后端（基于 vLLM）中统一文本生成与水印构建两条异步推理流，配合自适应调度与推理引擎优化，消除辅助模型与外部工具。
- **四项设计目标**：统一设计、效用保持、自适应协同服务、服务效率。

### 关键技术细节

- **异步协同服务（Asynchronous Co-serving）**：
  - 文本生成流自回归逐 token 解码；维护段缓冲区（segment buffer），在检测到句子边界时提取完整片段 `si`，作为水印请求提交给共享 LLM。
  - 文本生成继续解码后续 token，不等待水印完成；水印片段按原始顺序流式输出。
  - 复用 vLLM 优化：前缀缓存、连续批处理、请求优先级、分块预填充（chunked prefill）、共享 KV-cache 管理、统一 bf16 精度。

- **自适应协同服务调度器（Adaptive Co-serving Scheduler）**：
  - 每 K 个调度步更新水印准入比例 `rτ`：
    - `rτ = rmin + (rmax − rmin) · pτ`，其中 `rmin/rmax` 为下/上界，`pτ ∈ [0,1]` 为归一化水印压力。
  - **水印压力估计**：监控 FIFO 队列长度 `qτ` 与最旧请求等待时间 `wτ`：
    - `pτ = clip(max(qτ / Bmax, wτ / Wmax), 0, 1)`
    - `qτ/Bmax` 捕捉积压压力，`wτ/Wmax` 捕捉等待时间压力，取最大值以优先处理更紧急条件。
  - **混合批准入**：目标水印容量 `Bwm_τ = ⌊rτ · B⌋`（B 为共享 vLLM 支持的最大并发序列数），其余容量留给文本生成。

- **水印构建（指令引导候选生成 + 键控选择）**：
  - **指令引导候选生成**：使用同一 LLM 识别可水印位置 `Ii`（名词、动词、形容词、副词等），并生成上下文感知替换候选。
  - 水印提示 `Pi = [Pshared ; si]`，`Pshared` 为共享指令前缀（受保护信息规则、语义/事实约束、候选生成指令、few-shot 示例）；由于前缀相同，vLLM 前缀缓存可复用其 KV 状态。
  - 通过 vLLM 结构化输出解码约束为 JSON schema，得到候选集 `Ci = {wi,j : Ci,j | j ∈ Ii}`。
  - **键控候选选择**：采用 Tournament 选择 `Ri = T(k, Ci, si) = {c*_{i,j}}`，用秘密密钥 k 派生的伪随机性可复现但无密钥不可预测；应用替换得水印片段 `s̃i = Replace(si, Ri)`。

- **水印检测**：
  - 键控对比检测器：用双向 Transformer 编码器（RoBERTa-large）编码文本，将密钥 k 映射为确定性键嵌入，通过逐元素交互与绝对差组合文本/键表示做二分类。
  - 训练目标：检测损失（二分类）+ 对比损失（对齐匹配的文本-键对、分离不匹配对）。

- **复杂度**：
  - 时间：`Cwm = O(Cprefill(|Pshared|) + Σ Cprefill(|si|) + Σ Σ Cdecode(...) + Σ |Ii|M)`；自适应调度器仅常数时间开销。
  - 空间：`O(MLLM + MKV + Σ|Bu| + Σ|si| + Σ|Ii|M)`，仅保留一份 LLM 权重。
