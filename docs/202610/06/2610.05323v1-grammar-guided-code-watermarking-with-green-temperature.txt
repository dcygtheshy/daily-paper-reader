## ABSTRACT 

Large language model watermarking embeds detectable statistical signals during decoding, but the resulting changes to token probabilities can degrade generation quality. This trade-off is particularly important for code, where small changes in token selection can break syntax or alter program behavior. Existing code wa-termarking methods mitigate this risk through entropy-based insertion or syntax-aware token selection, but they do not directly construct the watermark over the set of continuations admitted by the current grammar state. We propose Grammar-Guided Code Watermarking with Green Temperature (GTCW), which integrates grammar-constrained decoding with probability-aware watermarking. At each de-coding step, GTCW restricts the candidate set to grammar-admissible tokens and partitions this support into keyed green and red subsets. At eligible high-entropy positions, green temperature reweights the green tokens according to the model’s relative preferences, strengthening the watermark signal while retaining the gram-mar constraint. Across five models and five benchmarks spanning four program-ming languages, GTCW achieves a mean AUROC of 73 .61% , compared with 

67 .83% for the strongest baseline, while maintaining a mean Pass@1 of 59 .18% 

versus 59 .58% for unwatermarked generation. Our implementation is available at 

https://github.com/hyundong98/GTCW .

Generation-time watermarking addresses this problem by embedding a de-tectable statistical signal into the generated code without retraining the underlying model (Kirchen-bauer et al., 2023; Zhao et al., 2024; Dathathri et al., 2024). Many generation-time watermarks partition candidate tokens into keyed green and red sets and mod-ify the sampling distribution in favor of the green set (Kirchenbauer et al., 2023; Zhao et al., 2024; Mao et al., 2025; Guo et al., 2024). For code, however, perturbing token probabilities can break syntax or alter program behavior. Existing code watermarking methods reduce this risk through entropy-based insertion or lexical and structural constraints (Lee et al., 2024; Kim et al., 2026; Guan et al., 2024; Guo & Cheng, 2025). These approaches improve the choice of watermark carriers, but do not directly construct the watermark over the token set admitted by the current grammar state. A second source of distortion comes from how the selected tokens are reweighted. Common green-list methods apply the same additive bias to all green tokens, including those that the model originally assigns low probability (Kirchenbauer et al., 2023; Lee et al., 2024; Kim et al., 2026). In code generation, promoting such weak candidates can move probability mass toward syntactically or functionally undesirable continuations rather than preserving the model’s relative preference within the green set. We propose Grammar-Guided Code Watermarking with Green Temperature (GTCW) to address both carrier selection and probability reweighting in code watermarking. For carrier selection, grammar-constrained decoding restricts the candidate set to admissible continuations, and GTCW constructs the keyed green and red partition only within this support. For probability reweighting, green temperature operates at eligible high-entropy positions and adjusts green tokens according to their model logits. This gives greater emphasis to candidates already preferred by the model rather than uniformly boosting all green tokens. Detection replays the same grammar and keyed partitioning procedure on the observed completion without requiring stored generation traces. We evaluate GTCW on five models and five benchmarks covering Python, C++, Java, and Go. Across the 25 model-benchmark configurations, GTCW achieves a mean AUROC of 73 .61% , com-pared with 67 .83% for the strongest baseline, while its mean Pass@1 is 59 .18% compared with 

59 .58% for unwatermarked generation. At TPR@5%FPR, GTCW reaches 41 .86% , compared with 

24 .50% for the strongest baseline. Figure 1 summarizes these aggregate results. 

## 2 RELATED WORK 

LLM watermarking. Generation-time watermarking embeds a detectable statistical pattern dur-ing decoding through logit modification or alternative sampling procedures (Kirchenbauer et al., 2023; Zhao et al., 2024; Kuditipudi et al., 2024; Dathathri et al., 2024; Wang et al., 2025). KGW introduced the soft green-list framework, which partitions candidate tokens into keyed green and red sets while biasing generation toward the green subset (Kirchenbauer et al., 2023). Unigram water-marking uses a fixed keyed partition and provides formal robustness guarantees under editing and paraphrasing (Zhao et al., 2024). STA-1 introduces an unbiased sampling rule aimed at reducing distortion in low-entropy regimes (Mao et al., 2025). Unbiased and distortion-free watermarking methods more broadly seek to preserve the original output distribution while retaining a detectable signal (Hu et al., 2024; Kuditipudi et al., 2024; Chen et al., 2025). These methods are directly appli-cable to pretrained models without code-specific training, which makes them natural references for our decoding-time setting, but they do not account for the grammatical structure that restricts token choice in code. Beyond additive green-list biasing, Permute-and-Flip develops a stable watermark-able decoder whose watermarking scheme preserves the underlying sampling distribution (Zhao et al., 2025). This direction is related to our goal of reducing watermark-induced distortion, but it redesigns the sampling rule itself and is not specialized to code or grammar-constrained carrier selection. We therefore treat it as a complementary general decoding approach rather than a code-specific baseline. 

Code watermarking. Code watermarking methods explicitly address the stronger structural con-straints of program generation. SWEET restricts watermark scoring to high-entropy positions (Lee et al., 2024), while STONE avoids watermarking syntax-critical tokens and applies the watermark only to non-syntactic categories (Kim et al., 2026). Both operate at decoding time without addi-2tional training, making them direct baselines for our setting. Other approaches incorporate learned structural information. CodeIP trains a type predictor and constrains next-token sampling according to predicted code-token types (Guan et al., 2024). ACW uses AST-aware training signals and se-mantic substitutability to adapt watermark insertion (Guo & Cheng, 2025). These approaches rely on learned or type-based structural guidance. In contrast, GTCW requires no auxiliary training and constructs a keyed partition directly over the token set admitted by the current grammar state. Code-GenGuard also uses training-based structural information, but targets model ownership rather than output attribution (Yang et al., 2026). It encodes watermarks through semantics-preserving trans-formations and verifies ownership using a trained watermark mechanism and trigger prompts. It is therefore complementary rather than directly comparable to our decoding-time output watermark. 

Grammar-constrained generation. Programming languages are commonly described by context-free or closely related grammatical abstractions. This makes grammar constraints a natural way to restrict code generation to structurally valid continuations. A line of work on grammar-constrained decoding enforces such constraints during LLM generation. SynCode uses CFG-based masking to restrict generation to tokens consistent with a target grammar, while XGrammar im-proves structured-generation efficiency through optimized grammar execution and persistent parser-state management (Ugare et al., 2025; Dong et al., 2025). In GTCW, watermark construction is defined over the state-dependent admissible support of the current grammar state, and the keyed green partition is formed only over permitted tokens. 

## 3 GRAMMAR -G UIDED CODE WATERMARKING WITH GREEN TEMPERATURE 

GTCW addresses two sources of distortion in code watermarking: the mismatch between vocabulary-level green partitions and the tokens that are actually admissible under the current pro-gram state, and the probability distortion introduced by uniformly biasing selected green tokens. We first formalize the former issue and then introduce grammar-guided partitioning, which constructs the watermark directly over the admissible token support. We next present green temperature for reweighting green candidates according to the model’s relative preferences, followed by the corre-sponding replay-based detection procedure. 3.1 CONDITIONAL GREEN -R ATE DISTORTION 

Let x denote the prompt and y = ( y1, . . . , y T ) the generated continuation. At decoding step t,

y<t is the generated prefix and ℓt(v) is the model logit for token v. The parser state st determines the admissible token set At under the current grammar state. Conventional green-list watermarks construct a pseudo-random partition over the model vocabulary V, with a nominal green fraction γ.Let Gt ⊆ V denote the green set at decoding step t. For code generation, however, only a subset 

At ⊆ V is admissible at a given program state. The effective green fraction among admissible tokens is therefore 

bγt = |A t ∩ G t||A t| . (1) If the green partition were sampled independently of At, we would expect E[bγt] = γ. For a realized partition, however, bγt can deviate from the nominal green fraction. This deviation is particularly relevant for context-dependent watermarks. Their partition seeds are commonly derived from a recent token window, so repeated local token contexts can reproduce the same green-red partition. Consequently, deviations in bγt may recur rather than average out across decoding steps. Moreover, the same local token context can occur under different parser states with different admis-sible supports, while still inducing the same vocabulary-level partition. For code watermarking, the relevant distribution is the one conditioned on tokens that can actually continue the current program. This motivates constructing the green-red partition directly over the state-dependent admissible sup-port, rather than partitioning the full vocabulary and conditioning on it afterward. 3.2 GRAMMAR -G UIDED PARTITIONING

4.2 MAIN RESULTS 

Table 1 compares the three models across five benchmarks. Across these 15 model-benchmark settings, GTCW achieves the highest TPR@5%FPR in every setting and the highest AUROC in 12 of 15 settings. The advantage is particularly pronounced on Qwen2.5-Coder (3B) and Llama3.1 (8B), while Qwen2.5-Coder (7B) shows a smaller AUROC margin but retains the same consistent advantage at the low-FPR operating point. At the same time, GTCW remains competitive in Pass@1 across the benchmarks, showing that the stronger detection is achieved without substan-tially degrading functional correctness. Appendix C.1 extends the comparison to Qwen3.5 (9B) and Gemma4 (12B). Across all five models and five benchmarks, GTCW achieves mean AUROC of 

73 .61% and TPR@5%FPR of 41 .86% , improving over the strongest baselines by 5.78 and 17 .36 

percentage points, respectively. Its mean Pass@1 is 59 .18% , compared with 59 .58% for Base. 

Variation across models. The magnitude of the detection gain varies noticeably across models. GTCW is particularly effective on Qwen2.5-Coder (3B) and Llama3.1 (8B), while the AUROC mar-gin becomes smaller on Qwen2.5-Coder (7B). This variation appears to be related less to parameter count itself than to how each model distributes probability over watermarkable positions. Green temperature is active only when the model retains sufficient uncertainty among grammar-admissible candidates, so a model that produces sharper distributions can provide fewer opportunities to ac-cumulate watermark evidence. This interpretation is consistent with Qwen2.5-Coder, where finite-score coverage drops from 88 .48% at 3B to 66 .51% at 7B despite the two checkpoints belonging to the same code-specialized family. Even in the 7B setting, however, GTCW retains the highest TPR@5%FPR on all five benchmarks, suggesting that the selected carrier positions remain effective when available. 

Variation across benchmarks. The benchmark differences reflect a different interaction between grammar constraints and the semantic requirements of the generated code. MBPP+ combines strong 6detection with almost unchanged Pass@1 relative to Base, suggesting that many of its watermarkable decisions can be reweighted without changing the final program behavior. Go similarly provides strong detection, although with a somewhat larger correctness decrease. C++ shows a different pattern. Although GTCW maintains high detection performance, it exhibits the largest mean Pass@1 decrease among the evaluated benchmarks. Our grammar filters token choices according to syntactic admissibility, but it does not enforce type consistency, API usage, or program semantics. This distinction is particularly relevant for C++, where a continuation can remain grammatically admissible while a small token-level change still affects compilation or execu-tion behavior. The result therefore highlights the role of grammar guidance as a protective constraint rather than a complete correctness guarantee. Despite these language-dependent effects, GTCW preserves aggregate functional correctness close to Base while maintaining substantially stronger detection. 4.4 GREEN TEMPERATURE SENSITIVITY 

Table 3 varies Tg from 0.3 to 0.7 while keeping all other settings fixed. Lower green tempera-tures consistently strengthen detection. As Tg approaches the base temperature T0 = 1 , the green-temperature adjustment becomes weaker, and both AUC and T@5 decrease across all five bench-marks. Mean AUROC falls from 84 .25% at Tg = 0 .3 to 79 .58% at 0.7, while mean TPR@5%FPR decreases from 57 .7% to 45 .5% . This trend follows directly from the green-temperature transforma-tion. As Tg decreases, probability becomes increasingly concentrated on green candidates already assigned high logits by the model, yielding a stronger watermark signal. At the same time, overall performance is not overly sensitive to moderate changes in Tg . In par-ticular, detection remains relatively stable around the default. Mean AUROC differs by only 0.75 

points between Tg = 0 .3 and 0.5, with the larger decline appearing as Tg moves closer to T0.Functional correctness is even less sensitive and does not follow a monotonic trend. Across the displayed range, mean Pass@1 varies only from 57 .63% to 58 .16% . This stability suggests that stronger multiplicative reweighting need not directly translate into lower code quality. ## 5 CONCLUSION 

We presented GTCW, a grammar-guided code watermarking method that constructs keyed green-red partitions over grammar-admissible tokens and uses green temperature to strengthen the wa-termark according to the model’s existing token preferences. Across five models and five bench-marks spanning four programming languages, GTCW achieves a mean AUROC of 73 .61% and TPR@5%FPR of 41 .86% , improving over the strongest corresponding baselines by 5.78 and 17 .36 

percentage points, respectively. Its mean Pass@1 is 59 .18% , about 0.4 points below the unwater-marked reference, showing that the stronger detection is achieved while largely preserving functional correctness. In particular, GTCW attains the highest TPR@5%FPR in all 25 model-benchmark configurations. Ablations reveal complementary roles for the two components. Grammar guidance improves mean Pass@1 by 2.23 points with little change in aggregate AUROC, while green temper-ature improves mean AUROC by 9.05 points and substantially strengthens low-FPR detection over additive bias with grammar retained. These results show that grammar guidance primarily protects generation quality, while green temperature provides the stronger detectable signal. GTCW also retains competitive detection under a range of local code transformations, although LLM rewriting substantially weakens the signal. Improving detection after large structural rewrites and reducing the runtime overhead of the current implementation are important directions for future work. 9AI USE STATEMENT

For each task and seed, all methods generate one sampled completion using the same decoding configuration. We use temperature T0 = 1 .0, top-p = 1 .0, no top-k filtering, a repetition penalty of

The watermark is applied only to the generated continuation, while preceding tokens remain available to context-dependent watermarking methods. For GTCW, we use γ = 0 .5, entropy threshold τ = 0 .9 nats, green temperature Tg = 0 .5, and context width w = 1 . Experiments use seeds 42, 43, and 44. 

Baseline implementations. We integrate Unigram, KGW, SWEET, STONE, and STA-1 into the same evaluation pipeline (Zhao et al., 2024; Kirchenbauer et al., 2023; Lee et al., 2024; Kim et al., 2026; Mao et al., 2025). 15 B.5 CODE TRANSFORMATION EVALUATION PROTOCOL 

We evaluate six transformation families with 13 settings on Qwen2.5-Coder (3B) outputs from the five benchmarks and seeds 42, 43, and 44. Each transformation is applied independently to the cor-responding clean completion, and only the generated continuation is modified. The original code prefix is preserved for reconstruction and replay detection. All watermarking methods are evaluated with the same transformation implementations and strength settings. Local edit selection uses de-terministic per-record seeds derived from the record identity, method, transformation, and setting. The LLM rewrite is stochastic but uses the same request procedure across all methods. Matched clean Base completions serve as the negative class for all transformation settings. Consequently, the reported metrics characterize detection after transformation relative to the clean negative distribu-tion and may also reflect transformation-induced score shifts. The reported AVG averages the 13 transformation settings and excludes the clean reference. 

Identifier renaming. We rename 25%, 50%, 75%, or 100% of eligible local variables. Tree-sitter is used to identify declarations and references within the generated continuation. We exclude ambiguous bindings, references that cross the code-prefix boundary or nested functions, and member or API identifiers. Selected variables and their accepted references are assigned fresh names that do not collide with existing identifiers or language keywords. The requested rate is measured over eligible variables. 

Formatting and comment removal. Formatting uses Black for Python, clang-format for C++, google-java-format for Java, and gofmt for Go. A temporary boundary marker is used to separate the preserved code prefix from the formatted continuation. Comment removal deletes removable comments while preserving line structure. For Python, docstrings in the generated continuation are also removed, with pass inserted when required to keep a body nonempty. Comments in the code prefix and protected directives such as Go build directives are left unchanged. 

Dead-code insertion. We request 1, 3, or 5 insertions at eligible statement boundaries inside func-tions. Each insertion adds a constant-false branch containing a local dummy assignment. For Go, the inserted block also includes a blank-identifier use of the dummy variable. Insertion sites are selected in deterministic pseudorandom order. When fewer eligible sites are available, all available sites are used and the achieved insertion count is recorded. 

Control-flow transformations. We request 1, 3, or 5 nonoverlapping edits at eligible syntax nodes. The implemented transformations include double negation of conditions, condition inversion with branch exchange, expansion of an else-if chain into nested branches, and equivalent Boolean-literal rewrites. Each requested step corresponds to one selected edit site. Overlapping or unsup-ported sites are excluded, and the achieved number of edits is recorded when fewer sites are available than requested. 

LLM rewriting. We use gpt-5-mini to generate one rewritten continuation through a struc-tured JSON response. The request includes the language, preserved code prefix, and original com-pletion, and asks for changes to control flow, data flow, or implementation structure while preserving the public API and program behavior. The response is restricted to code and may not introduce ad-ditional tests or Markdown wrappers. For MBPP+, where the generated continuation may include the function declaration, the public function name and signature are preserved. Invalid responses, unresolved prefix echoes, unchanged rewrites, and request failures are retried up to three times. If all attempts fail, the original completion is retained. The rewriter receives neither the watermark key nor detector feedback. 

Validation and failure handling. After transformation, the preserved code prefix and transformed continuation must pass Tree-sitter parsing. Transformations that fail this check fall back to the orig-inal completion. Successful partial transformations are retained, and both requested and achieved strengths are recorded. All outputs, including unchanged and failed transformations, remain in the reported metrics. These transformations are designed to preserve program behavior, but functional tests are not rerun after transformation. 16 Detection and aggregation. Watermark scores are recomputed on the transformed continuation using the original code prefix and the corresponding method configuration. For SWEET, model entropy is recomputed on the transformed token sequence using the generation-time entropy thresh-old. STONE uses its corrected detector with prefix length=1 and δ = 2 .0. AUROC and TPR@5%FPR follow Appendix B.2. Results are averaged equally over the five benchmarks and three seeds, and AVG gives equal weight to the 13 transformation settings while excluding the clean reference. B.6 EXPERIMENTAL ENVIRONMENT

C.4 GENERATED CODE EXAMPLES 

Figure 3 shows functionally correct and detected outputs for MBPP+/796, which asks for the sum of all values in a dictionary. All methods use Qwen2.5-Coder (3B) with the same code prefix, and every displayed completion passes the full MBPP+ test suite. The examples highlight how the methods differ in where watermark evidence is introduced. Uni-gram, KGW, and STA-1 apply their watermarking rule broadly across generated positions, including identifiers, syntax, and comments. For example, in the STA-1 output, repeated occurrences of the 19 local identifier sum are independently watermarkable. Such broad carrier selection provides many opportunities to accumulate signal, but also perturbs token choices at positions that may be impor-tant for the generated program. STONE excludes some syntax-critical token categories, but in this example a substantial portion of its scored signal appears in comments. SWEET instead uses en-tropy gating to avoid low-entropy positions. Its concise completion happens to contain only three scored positions, all of which are green. GTCW uses a more restrictive carrier condition that combines grammar admissibility, the carrier gate et, and the entropy gate. Its advantage therefore does not come from watermarking a broader set of positions. Rather, green temperature strengthens the signal within the selected admissible positions while preserving the model’s relative preference among green candidates. In the displayed completion, ten positions are scored and nine are green. The remaining scored red token further illustrates that GTCW biases, rather than forces, the green choice. Overall, the example reflects the intended design of GTCW: strong watermark evidence from selectively chosen positions without requiring broad token-level perturbation. Prompt
