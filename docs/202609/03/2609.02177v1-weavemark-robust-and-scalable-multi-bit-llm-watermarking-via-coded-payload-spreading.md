## 摘要
针对大型语言模型的多比特水印技术通过将用户可识别的消息嵌入到生成的文本中，实现了内容来源追踪。现有方法在提取精度、文本质量和载荷容量之间面临根本性的权衡。我们提出了WeaveMark，一种基于编码载荷扩展的鲁棒且可扩展的多比特大语言模型水印方案。WeaveMark通过多比特每令牌扩展提高了载荷容量，通过软判决纠错码提高了提取精度，并通过无偏多层重加权保持了文本质量，从而推动了这一权衡边界的前移。它还引入了专用的零比特层以实现可靠的水印存在性检测。实验表明，该方法在长消息和编辑文本场景下取得了显著提升。在200个令牌时，WeaveMark对32比特消息的匹配率达到89.8%，而BiMark仅为20.8%。在200个令牌的16比特消息遭受10%替换攻击时，WeaveMark保持了86.0%的匹配率，而BiMark仅为30.7%，同时保持了文本质量。我们的代码可在https://github.com/qkrrkd90-source/WeaveMark获取。

## Abstract
Multi-bit watermarking for large language models (LLMs) enables content source tracing by embedding user-identifiable messages into generated text. Existing methods face a fundamental trade-off among extraction accuracy, text quality, and payload capacity. We propose WeaveMark, a robust and scalable multi-bit LLM watermarking scheme based on coded payload spreading. WeaveMark shifts this trade-off frontier by improving payload capacity through multi-bit-per-token spreading, improving extraction accuracy through soft-decision error-correcting code, and preserving text quality through unbiased multilayer reweighting. It further introduces dedicated zero-bit layers for reliable watermark presence detection. Experiments show large gains, especially for long messages and edited text. WeaveMark achieves 89.8% match rate for 32-bit messages at 200 tokens, compared with 20.8% for BiMark. Under 10% substitution attacks on 16-bit messages at 200 tokens, it maintains 86.0% versus 30.7%, while preserving text quality. Our code is available at https://github.com/qkrrkd90-source/WeaveMark.

# WeaveMark 论文总结

## 1. 核心问题与整体含义（研究动机与背景）

大型语言模型在提供文本生成能力的同时，也被滥用于制造虚假新闻、钓鱼邮件、欺诈性评论等，因此对生成内容进行**溯源与归属验证**至关重要。

- 零比特水印只能判断文本是否来自某模型（是/否）；
- 多比特水印可在生成文本中嵌入**更长的用户可识别消息**（如用户 ID），实现细粒度溯源链条。

多比特水印的核心矛盾是**“不可能三角”**：

- 提取准确率：要求每个比特能被可靠恢复；
- 文本质量：不能明显扭曲原始文本分布；
- 载荷容量：消息越长，模型需嵌入的比特观测就越分散，出错概率越高。

现有方法不理想：

- **BiMark**：通过无偏多层重加权保证了文本质量和比特级提取可靠性，但其"每 token 嵌入一个比特"的设计限制了载荷规模。200 个 token 下嵌入 32 比特时匹配率只有 20.8%。
- **MPAC 与 Qu et al.**：通过分段嵌入提高容量，但使用了有偏重加权，当 δ 较大时文本质量明显劣化（BERTScore 从 30 左右跌至 ≤27.5）。

**WeaveMark 的核心含义**：在不牺牲文本质量的同时，将可嵌入的可靠载荷从 16 比特扩展到 32 比特以上，并将严重攻击下的恢复能力提升一个量级，整体推动现有权衡前沿。

## 2. 方法论

### 2.1 核心思想

WeaveMark = **编码载荷扩展**（coded payload spreading）+ 软判决纠错码（soft-decision ECC）+ 无偏多层重加权，在保留原有质量的同时提高比特利用率与鲁棒性。

其名称"weave"（编织）意指将编码后的比特以“编织”的方式分散到每个 token 的多个水印层中。

### 2.2 关键技术细节

#### (1) 编码载荷扩展：多比特/令牌嵌入

- 消息 m 先用 ECC 编码为 n 比特码字 c = E(m)；
- 每个令牌不再是只承载一个比特，而是**承载 κ 个比特位置**；
- 给定上下文 x₋ₕ，通过 PRF 选择 κ 个比特索引 P = {p₁,…,p_κ} ⊆ {1,…,n}；
- ℓ 个层按最大化均衡的原则分配给这些选中的比特位置（每比特获得 ⌊ℓ/κ⌋ 或 ⌊ℓ/κ⌋+1 层）；
- 这使得每个比特位置获得约 κT/n 个令牌的投票，而原来只有 T/n，从而在**不缩小词表分区**的前提下提高了每个比特的观测密度，解决了 BiMark 每比特投票严重不均的问题。

#### (2) 层洗牌

- 多层重加权中**越早的层信号越清晰**，后期的层信号会被前面的重加权干扰（文中提到十层中提取准确率从 72.20% 递减到 56.98%）；
- 用上下文种子对层索引做无序置换，避免某些比特位置长期获得固定的“好层/差层”，使各比特位置嵌入强度更加均匀，从而显著提高匹配率（16 比特×100 token：46.8% → 73.6%）。

#### (3) 保持无偏性

- 在正常随机化下不进行均匀采样（与 BiMark 相同），而是将基向量方向 ei = c(p_i) ⊕ b_i，其中 b_i ~ Bernoulli(0.5)，密钥由此生成；
- ei 仍以 50% 概率等于 0/1，因此 E[R(P)] = P，所有多比特层仍可在期望意义上保持原始 token 分布；
- 换而言之，选择哪些比特位置嵌入**不会破坏**无偏属性。

#### (4) 软判决 ECC 解码

- 收集所有投票后，为每个比特位置定义软可靠性分数 s[p] = v₁[p] − v₀[p]，
- 再按码本进行最大似然相关解码：
  - ĉ = argmax_c∈𝒞 Σₚ s[p]·(2c[p]−1)
- 这保留了大量经硬判决后会被丢弃的置信信息（如(100,99)和(100,0)原本是等效的，现在则不同）；
- 论文比较了 soft voting / LLR voting / hard voting，soft voting 在短文中优于 LLR，且始终优于 hard voting。

#### (5) 专用零比特层

- 现有方案零比特检测时不知道未知消息下的目标分区，唯一可行的方法是使用多数投票（即“max-over-partitions”），这会**人为增大非水印文本的统计量**，抬高显著阈值；
- 将 ℓz 层开辟为消息独立的“零比特检测层”：其分层与消息无关，可由上下文直接重建，因此不再需要使用 max-over-partitions 技巧；
- 对 FPR=1%，z-score 阈值被稳定在 ~2.3（比 BiMark 的 4.54–5.55 低很多）；
- 设定：total ℓ = 10，零比特 ℓz = 2；纯零比特模式下可用 ℓz = 10。

### 2.3 算法流程简示

**嵌入算法**

1. 编码 c ← E(m)；
2. 对每个新 token：根据 x₋ₕ 计算 PRF（b、p、s）；
3. 按 PRF 构建 ℓ 层均匀分布的层分配向量；若无上下文出现则跳过（即不重用上下文）；
4. 按 步骤 7 顺序施加无偏重加权；
5. 从干净文本 P 中抽取带水印 token。

**提取算法**

1. 对每个 token，重新恢复分配的比特位置 P 及掩码 b_i；
2. 估计方向 ê_i = 1{x_t ∈ Vⁱ₁}；
3. 恢复码字比特 ĉ = ê_i ⊕ b_i；
4. 更新投票 vc[p]；
5. 最终进行软判决 ECC 解码，得到消息 m̂。

**关键设置的参数**：窗口 h=2、层数 ℓ=10、κ=10、δ=1.0、top-K=50、τ=1.0、使用无偏 XOR 比特翻转。

## 6. 论文的主要结论与发现

1. **载荷可扩展性被大幅调整**：对于 32 比特原始消息×200 token，匹配率从 BiMark 的 20.8% 提高到 89.8%（4.3 倍）；对于 16 比特且只有 50 token 的情况下，也达到 75%（BiMark 为 4.84%）；
2. **对编辑攻击的鲁棒性**：在 200 token/16 比特下，10% 替换时 WeaveMark 的匹配率为 86.0%（BiMark 30.7%），20% 替换时 44.2%（BiMark 6.59%）；
3. **DIPPER 改写并不太阻碍**：即使采用“最激进”的 (20,20) 配置，16 比特下的匹配率仍达到 49.0%，而 BiMark 为 9.8%；
4. **文本质量保持能力**：摘要的 BERTScore 30.48，接近原文的 30.54；BLEU 略低于原文（23.15 vs 25.24），但优于所有偏置类方法，PPL 水平显示与 BiMark 相当，而无 BP 的测试方法超过 PPL > 35（无明显量化）上的所有方法；
5. **零比特层无失真扩展到零比特**：在 FPR=1% 下，200 token 的 TPR 达到 99.12%，优于 KGW 的 98.71% 与 SynthID 的 98.0%；（多比特分配下也可保留多比特优势）
6. 层洗牌是提升匹配率的巨大杠杆（表 2：16 比特×200 token 从 24% → 55.9%），这一点与 Bit-position influence 观测在全文设计中相吻合；
7. 在提取阶段引入 vote margin 作为软判决可靠性信号后，可在 100 token 的文本中嵌入 32 比特消息，匹配率比无 ECC 状态净提升 61.8% 或更多。

## 7. 局限性与未决问题

作者在正文与附录中也坦承了若干尚未完全解决的问题：

- **窗口大小不对称**：WeaveMark 与 BiMark 使用 \(h=2\)，而 MPAC/Qu 在理论上受限于有偏重加权，只能采用 \(h=1\)。这使得两者在“攻击后鲁棒性”对比中并非所有变量都相等。论文仅通过消融实验间接表明窗口不是唯一来源，但未给出在相同 \(h\) 下的直接对照结果，作者在附录中将这列为未来工作。
- **极短文本仍是瓶颈**：在 25 token 下，32 比特消息匹配率依然很低（即使加了 ECC 也不足 20%）。水印鲁棒性高度依赖每比特的观测投票数，极短文本对任何方法都具挑战性，但 WeaveMark 并没有根本解决信息论下界带来的限制。
- **攻击者自适应问题**：论文评估的是固定策略攻击（如同义词替换、DIPPER 改写）。如果攻击者知道 WeaveMark 的 κ 个比特位置选择规则及 ECC 码本，理论上可以使用“诅咒式”针对性扰动来同时影响多个比特的软投票。文中未对自适应敌手场景做安全建模。
- **无偏设计所容忍的方差**：无偏重加权在小 δ 下对单 token 分布改变很小，但也意味着嵌入信号幅度低，需要长上下文才能积累足够统计差异。这导致了它在 50 token 以下时不如某些有偏方法表现出众，而只能依靠更长的投票长度取胜。
- **多模型部署的密钥共享问题**：若不同发布方使用不同钥匙，多比特水印就无法跨模型统一验证；WeaveMark 未讨论在联邦/多模型发布场景下如何做标准化的密钥管理。

---

## 8. 客观总体评价与简评

### 优点

- **问题定位明确，技术路线系统性强**：将“每 token 单比特”扩展为“每 token 多比特投票”是自然且直接的容量解法；层洗牌和软判决 ECC 都是低成本却有显著收益的工程技巧，而非复杂晦涩的模型改动。
- **实验设计细致且自洽**：用组件消融揭示了每个设计的边际贡献；在消息长度、替换比例、token 数等多个维度连续变化，避免了单一阈值下的偶然性结论。
- **实用价值突出**：方法不需要训练任何模型、不需要访问模型内部梯度，只需解码时执行一次 PRF 和解码，可插拔到现有任何自回归 LLM 中。

### 不足

- **外部泛化验证有限**：核心结果只集中在 LLaMA-3-8B 和部分 Mistral-7B 上，未覆盖更大规模（如 70B 级）或极小型模型（如 1B 级）。虽然方法应具有模型无关性，但没有证据证明在实际生成分布差异很大的模型上仍能保持相同增益。
- **统计显著性证据缺失**：所有结果都缺少重复实验的标准差或置信区间，令人无法判断 89.8% vs 89.0% 之间是否只是噪声波动。
- **“水印检出”的公平性**：零比特检测对比中 BiMark 使用了早期报告中偏保守的阈值设定，而 WeaveMark 专用零比特层虽在理论上更优，但关于阈值校准的影响范围描述还能更细致一些。
- **未提及计算资源**：尽管推理无需训练，文中没有报告生成、注入、提取过程的具体耗时和硬件需求，阻碍了读者评估其实际部署成本。

### 综合简要评价

**WeaveMark 是一个提出高质量方案且论证扎实的工作**。它并没有引入复杂的对抗训练或神经网络，却靠着“编码扩展 + 层洗牌 + 软判决 ECC”三个模块组合出了远超现有方法的效果。其最终性能改进不能用单一模块解释，而是系统工程式的叠加，这也是其亮点之一。若未来能在更多模型、更长的消息位（>32 bit）以及自适应攻击场景下给出进一步实证，将会更具说服力。

## 9. 对“impossible triangle”推进的意义

- 传统观念认为：载荷容量与鲁棒性冲突是水印固有的。WeaveMark 表明，对每个比特位置收集多次非独立投票、并用错误纠正码的软判决来融合这些投票，可以同时突破这些限制——因为其本质是**用统计重复换取有效信噪比**，既避免了有偏重加权的质量损失，又越过 BiMark 的装载率瓶颈。
- 在“30% token 同义替换”攻击下，16 比特消息的匹配率从 BiMark 的接近不可用水平提升到可接受的 40–50% 区间；这已接近实际部署中对“在强改写后仍能溯源”的要求。

---

## 10. 潜在可延伸工作与建议

1. **在更高 κ 值 + 更长消息下做完整 Pareto 曲线**：可以系统性地论证在相同文本质量限制下，消息位最大能达多少（64 bit？128 bit？）；
2. **引入错误检测与信道模拟**：设计一个基于文本编辑概率的“虚拟信道”来最优化 ECC 码率，而不是固定使用 BCH 等码；
3. **把层洗牌从确定型 PRF 改成密码学安全的伪随机传输**：以抵御针对随机种子的逆向破解；
4. **将方法注入到解码后的 token 分布采样外**：尝试跨 token 的 soft 水印，进一步提升容量；
5. **计算资源透明化**：建议后续版本报告平均生成/注入/提取的单条文本耗时，使工业应用更可判断权衡。

---

总之，WeaveMark 提供了一个清晰、高效、直接可落地的多比特水印方案，真正把“单 token 单比特”推进成了“单 token 多投票 + 软判决纠错”的新范式，并通过严谨的消融实验夯实了结论——在论文当下的研究语境中是极具竞争力的 SOTA 水平。虽然仍存在少量统计严谨性与泛化验证问题，其提出的解码侧回收置信度、层洗牌等技巧，完全可能成为后续可逆/多比特文本水印设计的基本组件。
