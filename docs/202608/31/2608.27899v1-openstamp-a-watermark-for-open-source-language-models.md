## 摘要
随着大型语言模型（LLM）生成内容的日益普及，水印技术被认为是一种有前景的方法，用于将文本归因于LLM并将其与人类撰写的内容区分开来。一类显著的技术通过修改令牌采样概率，在生成的文本中嵌入微妙但可检测的信号。然而，此类方法不适用于开源模型，因为用户具有白盒访问权限，可以轻松在推理过程中禁用水印。在这项工作中，我们引入了OpenStamp，一种水印技术，通过仅修改最终投影（或去嵌入）层，将水印逻辑直接编码到模型权重中。通过在两个模型上的实验，我们表明OpenStamp实现了优越的检测性能，与先前方法相比，模型能力的退化最小。所植入的水印是显式设计的，并经过实证确认，相比于先前的开源水印，对释义攻击具有更强的鲁棒性，且更难通过事后微调来擦除。为了使开发者能够为其模型添加水印，我们发布了代码以及4个流行开源模型的水印版本。

## Abstract
With the growing prevalence of large language model (LLM) generated content, watermarking is considered a promising approach for attributing text to LLMs and distinguishing it from human-written content. A prominent class of techniques embeds subtle but detectable signals in generated text by modifying token sampling probabilities. However, such methods are unsuitable for open-source models, where users have white-box access and can easily disable watermarking during inference. In this work, we introduce OpenStamp, a watermarking technique that encodes the watermarking logic directly into the model weights by modifying only the final projection, or unembedding, layer. Through experiments across two models, we show that OpenStamp achieves superior detection performance, with minimal degradation in model capabilities compared to prior methods. The implanted watermark is explicitly designed, and empirically confirmed, to be more robust to paraphrasing attacks and harder to scrub off through post-hoc fine-tuning than prior open-source watermarks. To enable developers to watermark their models, we release our code alongside watermarked versions of 4 popular open-source models.

## 一、核心问题与研究动机

- **问题背景**：LLM 生成内容泛滥引发了对大规模虚假信息传播、舆论操纵等潜在滥用行为的担忧，因此需要可靠地区分 AI 生成文本与人类撰写文本的技术。
- **现有方法的缺陷**：主流水印技术（如 KGW）通过在解码阶段修改 token 采样概率或在推理时约束采样过程来植入信号，这类方法在开源模型场景下完全失效——因为用户拥有白盒访问权限，可以轻易绕过推理时的水印逻辑。
- **核心挑战**：在开源生态中，水印逻辑必须直接嵌入到模型权重内部，使水印无法通过修改解码过程或外部组件被禁用。已有的权重级水印方案（如 Unremovable 的固定偏置扰动、GaussMark 的权重高斯噪声）存在可被反向工程、难以嵌入、缺乏释义鲁棒性等局限。
- **本文贡献**：提出 **OpenStamp**，通过仅修改模型最后的 unembedding（投影）层权重，将水印逻辑直接编码进模型参数中，使水印在正常生成过程中自动生效，无需任何解码期干预，且对释义攻击和事后微调具有更强抵抗力。

## 二、方法论

### 核心思想
将传统 KGW 绿名单水印机制转化为一个**线性化的权重级实现**：通过修改 unembedding 矩阵，使模型在生成时对特定候选 token 产生稳定的偏好偏差，同时保证这种偏好随上下文语义动态变化，避免被简单破解。

### 技术细节

**1. 权重修改方式**
- 定义修改后的 unembedding 矩阵 $\tilde{U} = U + \Delta W$，其中 $\Delta W \in \mathbb{R}^{|V| \times d}$ 为水印偏置矩阵。
- 对任意隐藏状态 $h_t$，修改后的 logits 为 $\tilde{v}_t = Uh_t + \Delta W h_t$，其中 $\Delta W h_t$ 被称为 watermark logits，用于偏置 token 采样。

**2. 矩阵分解：$\Delta W = GSP$**
- **P（语义对齐投影矩阵）**：将原始隐藏状态投影到一个语义对齐空间，使得语义相似的句子在投影空间中彼此靠近。通过最小化投影状态与高质量句向量之间的 KL 散度（对比学习）来训练。这是 paraphrase 鲁棒性的关键。
- **S（选择器矩阵）**：将投影后的隐藏状态映射为 L 个候选绿名单上的软选择向量。通过 k-means 对投影状态聚类、再通过岭回归学习从状态到簇标签的映射。
- **G（绿名单矩阵）**：由 PRF 生成 L 个绿名单作为列向量，每个绿名单包含约 $\gamma$ 比例的词汇，对应偏置强度为 $\delta$，与 KGW 的超参数含义一致。

**3. 检测方法（LLR 评分）**
- 对给定文本序列 $x$，计算长度归一化的对数似然比：
$$\text{LLR}(x) = \frac{1}{T}\sum_{t=1}^{T} \log \frac{p_{\text{wm}}(x_t | x_{<t})}{p_{\text{orig}}(x_t | x_{<t})}$$
- 通过比较该分数与预设阈值来判断文本是否由水印模型生成。
- 检测过程无需原始 prompt（附录 O 有实验说明），只需一次前向传播分别计算水印模型和原始模型下的概率。

**4. 检测协议**：开发者公开水印模型 $\tilde{U}$，保留原始 $U$ 为秘密；检测以 API 形式提供；此协议要求模型原始权重未公开过。

## 七、方法亮点与优点

1. **设计巧妙**：将 KGW 绿名单逻辑线性化为三个矩阵的乘积，实现了可训练的语义对齐 + 动态绿名单选择，同时无需任何辅助模型参与生成或检测，适用于开源场景。
2. **权重级水印，无需推理干预**：水印完全编码在 unembedding 层权重中，用户无法通过修改解码策略将其绕过。
3. **多绿名单机制增强安全性**：通过 L 个候选绿名单动态选择，水印 logits 存在跨上下文的高度变异性（附录 M），不易被反向工程。
4. **成熟的检测协议**：开发者保留原始权重为秘密，检测以 API 提供，防止攻击者恢复水印偏移量。
5. **展示了对多种攻击的全面防御**：从释义、微调、量化到 unembedding 重置，覆盖面远超已有工作。
6. **工程贡献充分**：公开了代码与 4 个流行模型的水印版本，便于社区复现与部署。

## 八、不足与局限

1. **检测缺乏统计保证**：LLR 分数不是形式化的统计检验，没有已知零分布，无法给出严格校准的 p 值或置信区间。这意味着无法从概率上严格量化误报风险（论文明确以 Limitations 形式承认）。
2. **检测成本较高**：每次检测需要水印模型和原始模型各一次完整前向传播，比仅统计绿名单token比例的方法昂贵得多。
3. **适用条件有限**：要求原始模型的权重在发布前保持私密；对于权重已公开的既有模型，本方法不可用。
4. **软选择器的对齐损耗**：连续隐藏状态产生软选择向量，导致与实际绿名单的对齐不完美（附录 L），虽然检测受影响不大，但损失了部分效率。
5. **代码领域检测率下降**：在 Python 代码上 TPR 降至 84%–92%，明显低于文本场景；对于代码生成型 LLM 的实际应用可能需要额外适配。
6. **指令微调后检测率下降**：虽然在 RealNewsLike 上保持高水平（TPR ≈ 100%），但在 AlpacaEval 上 TPR@1%FPR 降至 45%–70%，说明对指令微调后的输出检测不够稳定。
7. **未报告资源开销**：训练 P 和 S 的具体算力消耗（GPU 数量、训练时长）未披露，影响复现成本的评估。
8. **攻击面尚未穷尽**：未考虑模型合并（merge）、权重扰动（noise injection）、针对水印的对抗训练等更复杂的攻击方式；附录 P 虽然讨论了 selector 反转攻击，但未做完整的攻击端到端验证。
