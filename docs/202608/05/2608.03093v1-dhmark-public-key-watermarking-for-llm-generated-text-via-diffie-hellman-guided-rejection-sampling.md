## 摘要
大型语言模型（LLM）水印为追踪生成文本的出处提供了一种重要机制。现有的统计水印通常有效且鲁棒，但大多数依赖私有检测密钥，这集中了验证过程并使公开审计复杂化。近期的公开或可公开验证的水印方案改善了密钥管理，但其中许多依赖于嵌入加密字符串的精确恢复，使得它们在令牌编辑、截断、复制粘贴和低熵生成情况下变得脆弱。本文介绍了DHMark，一种用于LLM生成文本的公钥水印框架。其关键思想是将载荷授权与有噪声的文本证据分离。签发者对绑定到公开上下文的短注册载荷进行签名，并将载荷扩展为许多单比特方程。在生成期间，Diffie-Hellman引导的令牌标记接口为每个候选令牌分配一个公共方程投票，采样器软性或有选择性地提升那些投票与授权载荷一致的候选。在验证期间，第三方验证者使用公共信息提取令牌投票，将其聚合成方程级证据，并仅对已签名的注册记录进行评分。这种设计避免了精确恢复长嵌入签名，而是将水印检测视为注册辅助的统计证据聚合。我们形式化了公开验证设置，分析了标签伪随机性、注册支持的正确性和采样失真，并在截断、替换、复制粘贴、错误上下文和普通生成攻击下评估了原型。在默认的32位配置中，DHMark在八种编辑条件下保持至少0.967的有效率，同时在三种阴性对照上产生0.000的接受率。

## Abstract
Large language model (LLM) watermarking provides an important mechanism for tracing the provenance of generated text. Existing statistical watermarks are often effective and robust, but most of them rely on private detection keys, which centralizes verification and complicates public auditing. Recent public or publicly verifiable watermarking schemes improve key management, yet many of them rely on exact recovery of embedded cryptographic strings, making them fragile under token edits, truncation, copy-paste, and low-entropy generation. This paper introduces DHMark, a public-key watermarking framework for LLM-generated text. The key idea is to separate payload authorization from noisy textual evidence. An issuer signs a short registry payload bound to a public context, and the payload is expanded into many one-bit equations. During generation, a Diffie-Hellman-guided token-labeling interface assigns each candidate token a public equation vote, and the sampler softly or selectively promotes candidates whose votes agree with the authorized payload. During verification, third-party verifiers use public information to extract token votes, aggregate them into equation-level evidence, and score only signed registry records. This design avoids exact recovery of a long embedded signature and instead treats watermark detection as registry-aided statistical evidence aggregation. We formalize the public-verification setting, analyze label pseudorandomness, registry-backed soundness, and sampling distortion, and evaluate a prototype under truncation, substitution, copy-paste, wrong-context, and plain-generation attacks. In the default 32-bit configuration, DHMark maintains at least a 0.967 valid rate across eight edit conditions while yielding a 0.000 acceptance rate on three negative controls.

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 核心思想

- **三级分离架构**：
  1. **认证层**：签发者签名一条绑定公开上下文的短注册载荷（如 32 比特标识符），存于注册表，防止任意载荷声明。
  2. **编码层**：将短载荷扩展为 N 个公开的"单比特方程"，生成时每个令牌对某个方程位投一票（噪声投票）。
  3. **采样层**：利用 Diffie-Hellman 引导的公开密钥标签接口，使采样器偏向选择投票与授权载荷一致的令牌；验证时用公开信息提取令牌投票，聚合成方程级证据，仅对签名注册记录打分。

### 2.2 关键技术细节

- **公开验证设置**：系统包含签发者、生成器、注册表、验证者四类角色，形式化为 `Π = (KeyGen, Authorize, WGen, Detect)`，其中 `Detect` 只使用公钥、公开上下文和注册表记录，不需要生成器的采样秘密。
- **Diffie-Hellman 采样函数（PKSF）**：
  - 采样密钥 `sk_samp = a`，公钥 `pk_samp = A = g^a`；
  - 将令牌条目 τ 哈希到群元素 `U_τ = HG(τ)`，计算 DH 值 `z_τ = U_τ^a`，再经 `Hash_lab` 提取为标签 `(i, b)`；
  - 由 DDH 假设保证：不知道 `sk_samp` 时，标签与均匀随机不可区分，从而防止公钥被滥用制造水印。
- **单比特方程扩展**：公开二进制矩阵 `G ∈ {0,1}^{N×ℓ}`，方程向量 `Y(m) = Gm mod 2`；每个方程由若干载荷位异或构成，多令牌投票同一方程，验证时按多数投票估计方程位。
- **本地上下文绑定**：令牌标记基于局部上下文 `c_t = (x_{t-h}, …, x_{t-1})` 而非绝对位置，使得删除/插入只影响局部跨度，检测器能快速重新同步。
- **生成算法（Algorithm 1）**：签发记录 → 推导 G 与 Y(m) → 逐位置计算候选令牌标签 → 在兼容集合上按 `P̃_t(· | M_t)` 采样；若无兼容候选则回退到普通采样以保证文本质量。
- **验证算法（Algorithm 2）**：逐令牌提取投票 → 按方程索引聚合 → 多数表决 → 仅对注册表中签名验证通过的记录计算 `score(X, m_R) = (1/|A(X)|) Σ 1[by_i(X) = y_i(m_R)]` → 需同时满足方程数、唯一方程数、方程矩阵 F₂ 秩等证据门限。
- **安全性质**：论文给出四个形式化结论——引理 1（DH 标签伪随机性）、引理 2（拒绝采样 KL 散度为 log(1/ρ_t)）、引理 3（多数投票 Hoeffding 集中界）、定理 1（注册表支持的正确性界，包含签名伪造、DDH 混合和统计假阳性三项）。

## 6. 主要结论与发现

- **默认配置下**：全部未修改的水印文本均被接受；突变删除、中部裁剪、后缀截断、复制粘贴、恶意后缀共五种条件下**有效率 1.000**；随机删除、随机替换、前缀截断三种条件下**有效率 0.967**；三个负对照接受率均为 **0.000**。
- **证据量 ≠ 认证**：普通生成和错误上下文文本仍能产生 85–88 个被接受方程、满秩，但无法与任何签名记录达到阈值，说明注册表一致性检验才是认证的关键。
- **参数敏感性**：
  - 阈值 0.5 为最佳平衡点；0.3 负对照虽通过但统计裕度不足，0.7 使身份检测降至 0.967、平均正检率降至 0.941；
  - 生成长度 1000–2000 tokens 为最优操作区间；500 tokens 在随机删除下仅 0.800，3000 tokens 因长文本退化出现性能下降（复制粘贴 0.867）；
  - 载荷越短越鲁棒：32 位均值 0.989、64 位 0.948、128 位 0.848，验证了"短注册标识符 + 注册表签名"的设计动机；
  - 本地上下文必不可少：h=0 时身份检测仅 0.900、平均正检率 0.815，h≥1 后显著提升，h=4 兼具鲁棒性与较低开销。
- **采样开销**：约 27% 位置使用质量保持性回退；采样成本在可接受范围内，但未对生成质量进行直接评测。

## 7. 优点（方法或实验设计上的亮点）

- **设计理念新颖**：将"载荷授权"与"噪声证据"分离，用签名注册记录替代长嵌入字符串的精确恢复，直接回应了公开验证与编辑鲁棒性之间的本质矛盾。
- **密码学与统计的有机结合**：基于 DDH 的标签不可预测性防止公钥被直接复制水印行为；DH 引导投票接口将私钥采样能力与公开检验能力解耦。
- **鲁棒性来源于冗余证据而非精确解码**：单比特方程、多数投票、本地上下文同步和注册表辅助评分形成了一整套抗噪机制。
- **安全语义界定清晰**：明确区分"包含签发者授权的证据"与"完整文档未被篡改"，并据此处理复制粘贴与恶意后缀场景，避免过度声称。
- **实验诊断细致**：不只看最终接受/拒绝，还报告方程覆盖、秩、回退率、匹配概率质量等中间指标，能解释检测成功或失败的原因。
- **形式化分析扎实**：提供三个引理和注册表支持正确性定理的直接证明，并诚实说明其安全性依赖的具体假设（DH-label、独立投票、EUF-CMA 签名等）。

## 8. 不足与局限

- **安全边界未完全突破**：当前原型使用"公开提取占位符"而非实例化具体的公开可检秘密标签原语；定理 1 是注册表支持的正确性声明，并非抵抗知晓完全公开谓词的检测器感知优化器。
- **语义级攻击未评估**：未测试改写、摘要、机器翻译等更符合现实攻击面的变换，而这恰恰是语义水印方法关注的核心场景。
- **缺乏文本质量直接评测**：未报告困惑度、重复率、语义相似度或人类偏好，回退率 27% 表明采样分布确有改变，但质量影响未被量化。
- **样本量有限**：每组仅 30 个 prompt，负对照零接受不构成对小误报率的严格统计估计；部分差异（如 0.967 vs 1.000）仅对应 1 个样本，不能作为决定性排序依据。
- **长文本退化原因未验证**：3000 tokens 时性能下降被推测为"重复性/局部集中"，但 CSV 中缺少直接重复指标，该解释仍是待验证假设。
- **对外部威胁模型的覆盖有限**：未讨论检测器感知的对抗性优化器、颜色感知令牌替换、反向工程攻击等更强威胁；复制粘贴仍视为出处模糊而非伪造问题，不提供文档级完整性保证。
